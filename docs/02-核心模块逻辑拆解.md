# 核心模块代码拆解

> 保存自会话分析。思维导图：[`docs/03-项目思维导图.md`](03-项目思维导图.md)、[`docs/04-核心模块逻辑思维导图.md`](04-核心模块逻辑思维导图.md)。交互版在 `docs/canvases/`。

## 总览

正式管道：`query_parser → prompt_builder → llm_client → database → result_formatter`，由 `main.ChatBISystem` 串联。

Python 是管道；**业务逻辑在 Prompt 字符串、test_cases、indicators.json**。代码层无循环依赖；知识层（口径）四处手写，容易漂移。

`error_analyzer`、`schema_generator`、`text2sql_v0/v1/v2` 与主链路平行或未接线。

---

## config.py

**职责**：导入即生效的配置单例。无类。

**流程**：`load_dotenv()` → `DB_CONFIG` → `LLM_CONFIG`。

**要点**：

- `password`：`os.getenv(...) or "123qwe"`，空串也落到默认密码
- `api_key` 无默认，失败延迟到请求时
- `temperature=0.1`、`max_tokens=1000` 写死
- 配置在 import 时冻结；`schema_generator` / v0–v2 自己读 env，与本模块分叉

---

## query_parser.py

**输入**：自然语言。**输出**：`{original_question, is_valid}`。

`parse`：strip + 非空。`validate`：读 `is_valid`。

`main.run` 只用校验；成功后 `build_prompt` 仍吃原始 `user_question`，**parsed 被丢弃**。预留意图/实体/时间归一化，当前无分支。

---

## prompt_builder.py（业务中枢）

**输入**：问题 + `use_few_shot` / `use_rules` / `use_guards`。  
**输出**：`(system_msg, user_prompt)`。

静态块：`SCHEMA`（五表+枚举+口径注释）、Few-shot×4、`RULES`×7、`ERROR_GUARDS`。

拼装顺序：

1. system：默认角色句；rules|guards 为真时加「严格遵守业务规则」
2. 必含 SCHEMA
3. 可选 RULES → Few-shot → ERROR_GUARDS
4. 【用户问题】+【要求】1–6（**永远注入**，含净额和汇率）
5. rules|guards 时追加第 7 条
6. 「请直接输出 SQL：」

调用差异：`main.run` 默认只开 Few-shot；`evaluator.__main__` 三层全开。

---

## llm_client.py

`__init__` 用 `LLM_CONFIG` 建 OpenAI 客户端。

`generate_sql`：system+user，`temperature=0.1`，取 `choices[0].message.content`，`re.sub(r'```sql|```', '')` 剥围栏。

不是成对抽代码块；围栏外解释会进 `execute`。无重试、不校验 SELECT。

---

## database.py

每次 `connect → execute → fetchall → close`。`description` 为空则列名为 `[]`。无只读、无超时、无行数上限。`validate_connection` 无人调用。与 evaluator 共用，金标和生产走同一执行器。

---

## result_formatter.py

空结果：「查询结果为空」。列宽 = max(表头, 单元格)+2，`ljust` 拼 ASCII 表。`len()` 按码点，中文会乱列。`format_error` 未被 CLI 使用。

---

## main.py（组合根）

`ChatBISystem` 写死 Parser / LLM / DB / Formatter。

`run`：

1. parse → validate（失败：无 sql）
2. `build_prompt(question, use_few_shot)` — 无 rules/guards 参数
3. `generate_sql`（异常不被 run 捕获，落到 CLI「系统错误」）
4. `execute` + `format` 包在 try；失败仍返回已生成 sql

CLI：有 argv 跑一次，否则 REPL（exit/quit/q）。

---

## evaluator.py

**主指标**：Execution Accuracy（两边 SQL 在真实库结果等价）。Exact Match 仅参考。

`evaluate_one`：generator → Exact Match（lower+空白折叠）→ 执行金标 → 执行生成 SQL → `_results_equivalent`。

等价判定：列数/行数必须同；任一侧 SELECT 不是纯聚合则比列名；比列名时行转 `{列: str(值)}` 再按键、按行排序；纯聚合按位置元组排序。括号深度切 SELECT 列表。

`sql_generator: Callable` 是全仓库唯一依赖倒置。`run_evaluation` 里 `cases=cases[:1]` 会只跑第一题。

---

## error_analyzer.py

见 `docs/01-error-analyzer-第一性原理.md`。零 import。义务启发式，时间检查有大小写 bug。

---

## schema_generator.py

离线：`SHOW TABLES` + `SHOW FULL COLUMNS` + 外键 → 文本。有外键时 comment 被 elif 丢掉。密码默认空串，与 config 不一致。**不写回** `prompt_builder`；手写 SCHEMA 仍多枚举和口径注释。

---

## text2sql_v0 / v1 / v2

教学平行宇宙：各自 OpenAI + 各自剥围栏，只打印 SQL 不执行。默认模型 `gpt-4o`（config 默认 `gpt-4`）。

| 版本 | 注入 | 目的 |
|---|---|---|
| v0 | 角色 + 问题 | 无 Schema 时胡编 |
| v1 | Schema + Few-shot + 5 条要求 | 上下文抬准确率 |
| v2 | v1 + CoT + 更严约束（汇率、completed） | ICIO / 思考链 |

---

## 知识层耦合（改「收入」要碰四处）

| 资产 | 收入定义 | 对齐 |
|---|---|---|
| RULES | net_amount + 汇率折人民币 | — |
| M02 expected_sql | SUM(net_amount)，无汇率 | 否 |
| error JOIN 检测 | 无汇率表且已写 currency 才报 | 弱于 RULES |
| indicators.json | SUM(net_amount * rate_to_cny) | 与 RULES 近 |

降耦合优先：单一口径源 → main 与 evaluator 共用 Prompt 开关 → 失败样本接入 analyzer → Parser 用起来或删掉。
